# AGENTS.md｜劇場日誌研究所

## 專案目的
建立繁體中文的劇場觀演與知識整理網站，協助使用者保存個人觀演心得、查找台灣劇場作品紀錄，並認識劇場製作與技術知識。

## 核心原則
1. 使用臺灣繁體中文，文字自然、清楚，不使用簡體中文。
2. 區分「可查證的外部資料」與「使用者個人心得」。
3. 外部資料必須保留 `source`（來源網址）及 `sourceName`（來源名稱）。
4. 不得自行補造演出日期、場地、票價、演員名單、劇情或得獎紀錄。
5. 未查證欄位使用「資料未載明」，不可猜測。
6. 日記資料不得冒充使用者真實經驗；示範內容須明確標記為示範。
7. 尊重來源網站著作權；只整理必要的基本事實與短摘要，不複製整篇文章或影像。

## 技術規範
- 靜態網站：HTML、CSS、原生 JavaScript。
- 資料放在 `data/` 的 JSON 檔案。
- 不使用需要伺服器端執行的框架或資料庫。
- 網站必須可部署於 GitHub Pages。
- 連結使用相對路徑，避免寫死本機路徑。
- 使用 `fetch()` 讀取 JSON；本機預覽請以 `python -m http.server 8000` 啟動，不要直接用 file:// 開啟。

## 資料結構
### productions.json
每筆作品包含：`id`、`title`、`year`、`creator`、`role`、`category`、`note`、`sourceName`、`source`。
`year` 代表來源資料記載的作品年份，不代表目前仍在演出。

### knowledge.json
每筆知識包含：`id`、`title`、`category`、`content`、`sourceName`、`source`。
內容需以自己的話摘要，並連結原始來源。

### diary.json
每筆日記包含：`id`、`title`、`date`、`venue`、`content`、`tags`。
只有使用者親自輸入的內容才可標記為個人觀演心得。

## 新增頁面工作流程
1. 先確認需求與新增頁面目的。
2. 檢查本檔案規範及現有資料結構。
3. 優先重用既有導覽、卡片、標籤與字體樣式。
4. 新增資料時同步補上來源網址及來源名稱。
5. 不確定的事實標示「資料未載明」，不得推測。
6. 檢查所有相對路徑、JSON 格式、手機版版面與 GitHub Pages 路徑。
7. 修改完成後列出新增或修改的檔案及需要人工確認的事項。

## 設計規範
- 主色：酒紅 `#713b4a`；背景：暖米白 `#f7f3ed`；文字：深灰褐 `#302a29`。
- 視覺方向：編輯式、溫暖、安靜、有劇場節目冊的質感。
- 卡片圓角適中、留白充足，避免過度動畫。
- 桌機與手機皆需可讀、可操作。
